# DeepSeek JSON hypothesis verification — 2026-09-28

Scope: DeepSeek JSON observation/auth, history read, active branch, typed fragments, signed original text downloads, bridge and picker/metrics boundaries. Other source behavior, DOM capture, summarization, destinations and toggles retain their behavior.

| Reported hypothesis | Evidence and decision |
| --- | --- |
| Wrong chat during handoff | Confirmed. The picker read DeepSeek identity only after awaiting the handoff. With a valid response for the newly selected chat, original capture succeeded. Pin the destination-click path and reject identity changes before requests. The actual picker function is regression tested. |
| Unknown user-visible roles/fragments silently lost | Not confirmed for normal current use. Code skips types outside its own-text contract, but inventing a role/fragment can only prove that skip, not that DeepSeek emits visible own text there. Native-derived fixtures use USER/ASSISTANT with REQUEST/THINK/RESPONSE/FILE; checked public evidence did not establish another visible own-text type. Tool payloads remain excluded. Leave extraction unchanged. |
| Legitimate code uploads lost | Confirmed. DeepSeek web-client upload documentation includes ordinary source/config/data files; the old five-extension list dropped `.py`/`.js` files and could remove their entire attachment-only user turn. Extend the bounded plain-text extension list. Retain signed-host/ID, parse status, MIME, fatal UTF-8, original byte-count and size checks; binary/Office/PDF/image files remain excluded. |
| `incomplete_message: false` is a valid completed value | Not confirmed. Current native-derived completed fixtures use null; firsthand frontend-derived schema documentation describes this field as string or null, with null on completion. No observed complete false value was found. Keep the existing check instead of widening it based on a made-up fixture. |
| Away-and-back navigation escapes cancellation | Confirmed during hook readiness and queued response delivery, when MAIN's network listeners are absent. Both original cases succeeded. A bridge latch now spans the entire capture and removes listeners on every exit. Existing cancellation during the network read stays intact. |

One directly related data-loss bug was also reproduced: DOM cleanup at the transfer-metrics boundary changed NBSP inside original code strings. DeepSeek JSON now preserves those strings through that boundary. Existing summary outer-transcript trimming is unchanged.

Primary author evidence for supported web uploads: [current web-client upload documentation](https://github.com/pooraddyy/deepseek-free#supported-file-types) and [published package documentation](https://pypi.org/project/p2d-deepseek/0.2.2/). Official model API file docs describe a different API and were not used to infer web history behavior.
