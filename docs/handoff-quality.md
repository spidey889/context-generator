# Handoff quality experiments

A good handoff lets the next assistant address the latest user request without asking for information the conversation already supplied. Fluent prose and correct headings are insufficient if the actual draft, corrected equation, failing CSV row or unselected options disappear.

For focused manual summary work, start with [CapContextBench v1](../evaluation/capcontext-bench/README.md): six cases across preservation, grounding and long-history recall, source-reviewed scores and matched failure patterns across prompts/models. It is outside the regular test suite and never runs on pushes. The larger historical experiments below remain evidence, not automatic benchmark scores.

The current v19 candidate retains master's fuller fact/source/status collection and final checks, removes illustrative facts, and preserves the pending request and current work product. It adds four selective handoff adaptations: stated decision reasons, failed attempts with observed results, separately scoped implementation/test/deployment status, and useful artifact pointers supplementing essential content. The [adaptation comparison](handoff-quality-adaptations.md) records the rationale; the [fresh dedicated-key comparison](handoff-quality-test-key-comparison.md) completes the previously unavailable regressions and long histories. The shorter v15-v17 contracts produced unsupported additions despite repeated wording refinements; the [v15 comparison](handoff-quality-v15-comparison.md) remains historical evidence. General quality improvement across models is not established.

`evaluation/handoff-quality-cases.json` covers six development tasks plus a fresh review-only case introduced after v14 was fixed. Its critical facts include exact draft text and reproduction evidence, not just names/numbers. Manually review every generated handoff for unsupported implications and whether the next assistant can actually continue. Lexical checks can miss paraphrases or count quoted/rejected text as present; never use them alone as semantic proof. See the [full-output review](handoff-quality-review.md) for observed failures, replaced approaches and remaining limits.

Use the owner's dedicated testing keys for live comparisons. The Windows-user-encrypted credentials live outside the repository at `%LOCALAPPDATA%\CapContext\testing\test-a.credential.xml` and `test-b.credential.xml`; the first and second supplied keys map to those slots. Never put their values in this document, reports, memory or production configuration. The local wrapper overrides inherited credentials for the child process and restores the prior environment afterward. Missing/decryption-failed test credentials stop the run rather than borrowing a production/development key.

```powershell
& .\scripts\compare-summary-with-test-key.ps1 -TestKey test-a -Model ling -BaselineRef a95254190755a55c09341c6626301012b1805726 -Cases evaluation/handoff-adaptation-cases.json -Repeats 2 -Output evaluation/results/handoff-comparison.json
```

The wrapper accepts `-Model ling`, `dots` or `qwen` and `-TestKey test-a` or `test-b`. A test-only fetch guard requires the selected credential, one of those configured routes, zero prompt/completion/request prices and denied data collection. Its private per-key ledger counts every attempted generation before sending, including HTTP failures, caps usage at 50 in a rolling 24-hour window, and spaces reservations at least 3.1 seconds apart. The file lock prevents concurrent budget overspending; corrupt or locked ledgers fail closed instead of resetting quota. Reports contain only the key slot and local usage, which are not a claim about server-side remaining quota. OpenRouter also applies account/provider limits; keys from one account may share the account cap ([official free-tier guide](https://openrouter.ai/blog/tutorials/how-to-get-the-lowest-cost-llm-inference-on-openrouter/)).

Use `--long-history` with the original `evaluation/handoff-quality-cases.json` fixture to include deterministic 90,000-character draft and 280,000-character corrected-design variants. The option depends on those original case IDs and cannot be combined with the adaptation fixture. Complete original turns stay in order, with the correction between two blocks of unrelated synthetic history. These exercise the large and extra-large profiles. Use `--case-id corrected-export-design-long-280000 --long-history` with the original fixture to isolate a costly case; reports record the selection and runner hash. This exercises recall under distraction, but does not reproduce every real conversation.

Before merging for quality, obtain generated baseline/candidate pairs, inspect full outputs against all five continuation criteria and repeat failure-prone cases. If the candidate loses constraints, invents work or drops the current work product, revise or remove it. Passing code tests establishes compatibility, not summary quality.
